# RPC-NCN value proposition

RPC-NCN builds a verifiable RPC layer whose reliability, integrity, and latency guarantees directly trace back to the implemented components and their automated verification suites in the [RPC-NCN-core repository](https://github.com/BSC-aujl/RPC-NCN-core).

## Reliability & availability
The gateway, operator nodes, and on-chain interval/epoch state machines orchestrate deterministic round windows so that every request either produces a stake-weighted proof or surfaces an inconsistency before the interval closes. Gateways fan out requests, collect ≥2/3 stake agreement, and coordinate attestations, while the Anchor-based contracts consolidate operator proofs and flag offenses for later epochs. Continuous verification—[`RPC-NCN-core/integration-tests/run-tests.sh`](https://github.com/BSC-aujl/RPC-NCN-core/blob/main/integration-tests/run-tests.sh) (all), [`RPC-NCN-core/tests/run-tests.sh`](https://github.com/BSC-aujl/RPC-NCN-core/blob/main/tests/run-tests.sh) (gateway), and [`RPC-NCN-core/tests/run-tests.sh`](https://github.com/BSC-aujl/RPC-NCN-core/blob/main/tests/run-tests.sh) (contracts)—keeps the scheduling, fan-out, and interval state machines exercised end-to-end.

## Integrity & accountability
Stake-weighted quorum enforcement is mirrored from the gateway to the contract and client-SDK. Operators build canonical hashes, signer bitmaps, and proof identifiers that the gateway aggregates and the contract re-validates during epoch finalization. `cargo test` inside the [RPC-NCN-core/operator-node](https://github.com/BSC-aujl/RPC-NCN-core/tree/main/operator-node) tree validates the proof builder, signer ordering, and attestation serialization, while the gateway and contract suites ([`RPC-NCN-core/tests/run-tests.sh`](https://github.com/BSC-aujl/RPC-NCN-core/blob/main/tests/run-tests.sh) with the gateway and contracts targets) confirm that only quorum-approved hashes are accepted and recorded.

## Latency & SLA readiness
Interval windows and epoch finalization provide the conceptual SLA bounding: requests are admitted once per interval, and canonical proofs are finalized before epoch cutoffs. The integration harness ([`RPC-NCN-core/integration-tests/run-tests.sh`](https://github.com/BSC-aujl/RPC-NCN-core/blob/main/integration-tests/run-tests.sh)), local e2e runner ([`RPC-NCN-core/tests/e2e/run-local-e2e.sh`](https://github.com/BSC-aujl/RPC-NCN-core/blob/main/tests/e2e/run-local-e2e.sh)), and [`RPC-NCN-core/scripts/preflight-e2e.sh`](https://github.com/BSC-aujl/RPC-NCN-core/blob/main/scripts/preflight-e2e.sh) verify that the gateway/operator/contract choreography produces proofs within those configured windows, which is the measurable baseline for any future SLA definition.
